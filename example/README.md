# zenstack-validator example

This folder shows how to use the **zenstack-validator** plugin to generate class-validator DTOs from a ZenStack schema,
and how to derive Nest-style create/update DTOs with **mapped types**.

## Prerequisites

- Node 18+
- pnpm (or npm/yarn)

## Setup

From the **repository root** (so the plugin can be linked):

```bash
# Install root dependencies and build the plugin
pnpm install
pnpm build

# Install example dependencies (links the plugin)
cd example
pnpm install
```

Set a dummy `DATABASE_URL` so the schema is valid (Prisma/ZenStack require it even if you only use the validator
plugin):

```bash
export DATABASE_URL="postgresql://user:pass@localhost:5432/db"
# or add a .env in example/ with: DATABASE_URL="postgresql://..."
```

## Generate DTOs

```bash
pnpm generate
```

This runs `zen generate`, which:

1. Reads `schema.zmodel`
2. Runs the **zenstack-validator** plugin
3. Writes `generated/validators.ts` with `UserDTO`, `PostDTO`, etc.

## Mapped types

See [`mapped-types.ts`](./mapped-types.ts) for a full walkthrough. Bind the schema once, then derive DTOs:

```ts
import {
  CreateMappedTypes,
  CreateType,
  UpdateType,
  chain,
  OmitPK,
  OmitRelations,
  mappedTypeCustoms,
  type SchemaMappedTypeFn,
} from "zenstack-validator/mapped-types";
import { PartialType } from "@nestjs/mapped-types";
import { schema } from "./generated/schema";
import { UserDTO, PostDTO } from "./generated/validators";

type AppSchema = typeof schema;

const customUpdateType: SchemaMappedTypeFn<AppSchema> = (schema, model, dto) =>
  PartialType(OmitRelations(schema, model, dto));

const userPatchType: SchemaMappedTypeFn<AppSchema> = (schema, model, dto) =>
  chain(schema, model, dto).pipe(OmitPK).pipe(OmitRelations).pipe(PartialType).build();

const mapped = CreateMappedTypes(
  schema,
  mappedTypeCustoms(schema)({
    updateType: customUpdateType,
    userPatchType,
  }),
);

export class CreateUserDTO extends mapped.createType("User", UserDTO) {}
export class UpdateUserDTO extends mapped.updateType("User", UserDTO) {}
export class UserPatchDTO extends mapped.userPatchType("User", UserDTO) {}

export class CreatePostDTO extends CreateType(schema, "Post", PostDTO) {}
export class UpdatePostDTO extends UpdateType(schema, "Post", PostDTO) {}

export class PatchUserDTO extends mapped
  .chain("User", UserDTO)
  .pipe(OmitPK)
  .pipe(OmitRelations)
  .pipe(PartialType)
  .build() {}
```

| Helper | Purpose |
| --- | --- |
| `CreateMappedTypes(schema, customs?)` | Bind schema; optional customs add/override helpers |
| `CreateType` / `createType` | Omit computed, auto-generated, and relation fields |
| `UpdateType` / `updateType` | `CreateType` + Nest `PartialType` |
| `OmitRelations` / `OnlyRelations` | Drop or keep relation fields |
| `OmitFK` / `OnlyFK` | Drop or keep foreign-key scalars |
| `OmitPK` / `OnlyPK` | Drop or keep primary-key fields |
| `OmitScalars` / `OnlyScalars` | Drop or keep scalar fields |
| `OmitComputed` / `OmitAutoGenerated` | Drop computed / defaulted fields |
| `chain(...).pipe(...).build()` | Compose schema-aware and Nest operators type-safely |

Run the example (typecheck + validate sample payloads):

```bash
pnpm mapped-types
```

## Schema overview

- **User**: `email` (@email), optional `name` (@trim, @lower), `score` (@gt(0), @lte(100)), `role` (enum), `createdAt`.
- **Post**: `title` (@length(1, 200)), optional `content`, `published` (boolean), `userId` FK + `user` relation.

The generated `validators.ts` uses decorators from **class-validator**, **class-transformer**, and
**zenstack-validator** (Gt, Lt, Trim, LowerCase, etc.).

## Enums

The schema defines a `Role` enum. The plugin generates an import like `import { Role } from "./models"` in
`validators.ts`. This example includes a stub **`generated/models.ts`** so that import resolves without running
ZenStack’s full codegen. In a real app you’d replace it with your generated enums or define enums in that file.
